# PII匿名化ツール(ローカルLLM連携プロトタイプ)

社内PC1台で完結する、外部通信なし(初回モデルDL時を除く)のPII匿名化
デスクトップアプリ(プロトタイプ)。Ollama等の常駐サービスは使わず、
`llama-cpp-python` でGGUFモデルをアプリのプロセス内に直接ロードする構成。

## レイアウト
左から [匿名化後プレビュー] [対応表(編集可能)] [原文入力]

## 使い方(セットアップ)

```bash
# 1. Python依存パッケージ(Windowsならプリビルドwheelが降ってくるので数十秒で完了)
pip install -r requirements.txt

# 2. (任意, 推奨) 人名/組織名/地名の検出精度を上げるため
pip install spacy ginza ja-ginza

# 3. アプリ起動
python3 main.py
```

モデル(GGUF)は初回、アプリ内の「モデル準備」ボタンを押した時に
HuggingFaceから自動ダウンロードされ、**プロジェクト直下の `models/` フォルダに
直接配置**されます(既定: bartowski/Qwen2.5-7B-Instruct-GGUF のQ4_K_M量子化版、
約4.5GB)。`models/` に該当ファイルが既に存在する場合は一切ネットワークに
アクセスしません。

### 配布(他PCへのコピー)について

`models/` フォルダごとプロジェクト一式を社内共有やUSBでコピーすれば、
コピー先のPCは**ダウンロード不要・ネット接続不要**でそのまま動きます。
Ollamaのような共有キャッシュ(`~/.cache/...`)やユーザーごとの設定に依存しないため、
「1台でダウンロード → フォルダごと配布」という運用がしやすい設計にしています。

## 使い方(アプリ内)

1. 起動直後、上部の「モデル準備(初回はDL)」ボタンを押しておく(初回は数分かかる)
2. 「メール取得」→ Outlookの受信トレイから最新の未読メール本文を原文欄に取り込む
   (pywin32でローカルのOutlookデスクトップアプリをCOM操作するのみで、外部通信は
   発生しない。Outlook未起動時などはエラーメッセージを表示)。取得したメールは
   自動で既読に変わる(同じメールを繰り返し取得しないようにするため)。
   もちろん原文欄に手動で入力・貼り付けしても良い
3. 「匿名化対象を検出」→ 辞書突き合わせ・正規表現/NER・ローカルLLMを、非エンジニアが
   手法の違いを意識しなくて済むよう一連の流れでまとめて実行する。
   メールアドレス・電話番号・郵便番号などの定型PII、(GiNZA導入済みなら)
   人名・組織名・地名、過去に確認済みの `pii_dictionary.csv`(マスター辞書)との
   一致、ローカルLLMによる見落とし検出が、すべて対応表に追加される
   (タグ自体は `[TYPE_連番]` の形で機械的に振られる)。ローカルLLM推論中は
   上部バーに「🧠 ローカルLLM推論中...(N秒経過)」と経過秒数が表示される
   (トークン単位の進捗は`llama-cpp-python`側に無いため、経過時間のみの簡易表示。
   「タグ割当」でのローカルLLM呼び出し中も同様に表示される)
4. 対応表は自由に編集可能。「手動追加」した行は種別=OTHERで仮のタグ
   (`[OTHER_連番]`)が即座に入るので、「元の値」を入力後、「タグ割当」を押すと
   ローカルLLMが原文を文脈に種別(PERSON/ORG/LOCATION等)を判定し、
   タグも判定後の種別のものに振り直す。「手動削除」「出現順に並替」も対応表の
   直下にある
5. 「プレビュー更新」→ 対応表を原文に適用した結果が
   左端に表示される。このとき、対応表のうちまだ登録されていない「元の値」は
   プロジェクト直下の `pii_dictionary.csv`(マスター辞書、Shift-JISで保存する
   ためExcelでそのまま開いて確認・編集可能)に自動で追記される。毎回の
   検出品質だけに頼らず、一度人手で確認した値を蓄積し、次回以降は
   「匿名化対象を検出」時に自動で対応表へ差し戻すための仕組み
6. 「🤖 AIによる返答生成」→ 左下の「どういう返信をしたいか」欄の内容と、
   左端のプレビュー(匿名化後の文章)を `reply_prompt_template.txt` に埋め込み、
   Gemini APIに送信して返信文の案を生成する(外部に送るのは匿名化後の文章のみ)。
   税務・会計についての具体的な質問には、Google検索によるグラウンディングを
   有効にして実際にWeb検索した上で回答する(単純な確認・お礼メールでは検索は
   行われない)。生成結果は自動的に②タブへ切り替わり、「AIによる返信案(匿名化)」欄に
   反映されたうえで匿名化解除まで自動実行される。実際に参照したWebページ(根拠)が
   あれば②タブ右下(その欄の下)に一覧表示される。匿名化解除後プレビューの末尾には、
   プロジェクト直下の `署名.txt` があれば自動で付け足される(無ければ付けない)
7. ②タブの「匿名化解除後プレビュー」直下の「返信メール作成」→ 現在の対応表・返信案で
   プレビューを作り直したうえで、Outlook標準の「返信」機能(引用を自動生成)で
   元のメールへの返信を作成し、その本文の先頭にこの返信案を差し込んだ状態でOutlookの
   作成画面を開く(メール取得でOutlookから取得したメールに対してのみ実行可能。
   送信は行わず、必ず内容を確認してから自分で送信する)。隣の「削除」は①②タブの
   全テキストエリアと対応表を
   まとめてクリアする(1件対応し終えて次のメールに移る際のリセット用)

## Ollamaを使わない理由(設計判断)

- 他プロジェクトでの使い回し予定が無いため、Ollamaという汎用モデル管理アプリを
  1つ丸ごとインストール・常駐させる必要性が薄いと判断
- `llama-cpp-python` はOllamaが内部で使っているのと同じ`llama.cpp`エンジンの
  Pythonバインディングで、推論速度は同等。バックグラウンドサービスが不要になる分、
  配布(社内展開)がシンプルになる(PyInstallerで1つのexeに同梱しやすい)
- モデルファイル(GGUF)はHuggingFaceから直接取得する

## 設計メモ

- `pii_core.py`: GUI非依存の検出・適用ロジック(正規表現+spaCy/GiNZA NER)
- `local_llm.py`: `llama-cpp-python` を使ったローカルLLM推論(Ollama不使用)。
  モデルはプロセス内でシングルトンとして保持し、初回のみロード
- `main.py`: customtkinter + tksheet によるGUI本体
- `gemini_client.py`: Gemini APIとの通信(このアプリで唯一の外部通信、送信するのは
  匿名化後の文章のみ)。APIキーは `gemini_api_key.txt`(gitignore対象、要書き換え)、
  プロンプトテンプレートは `reply_prompt_template.txt` から読み込む。
  `gemini_api_key.txt` には1行に1つずつ、改行区切りで複数のAPIキーを書ける。
  上から順に使い、あるキーがレート制限(429)に達したら次の行のキーに自動で
  切り替えて再試行する(1つしか無い場合はそのキーのみで、これまで通り動作する)
- LLM呼び出し・モデルロードは必ず別スレッドで実行し、GUIがフリーズしないようにしている
- 対応表は「元の値の長い順」に置換することで、短い値が長い値の一部として
  誤って先に置換される事故(例: 「田中」が「田中太郎」の一部として誤爆)を防止
